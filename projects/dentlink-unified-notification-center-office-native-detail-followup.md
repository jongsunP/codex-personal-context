# 치과앱 자체 주문 상세와 알림 랜딩 후속

## 사용자 결정 · 2026-11-13

- 알림센터는 1.94.0 릴리즈를 준비한다. 그보다 앞선 1.93.0 작업으로 **치과앱에 WebView 대신 자체 주문 상세 스크린이 추가될 예정**이라는 사용자 안내를 받았다.
- **치과앱만 대상**이다. 기공소앱은 아직 자체 주문 상세가 생기지 않으므로 같은 변경 대상으로 묶지 않는다.
- 지금은 기록만 한다. 1.93.0 배포 후 반영된 실제 코드/앱 버전을 기준으로 알림센터 랜딩과 필요한 영향 범위를 점검한다. 기존 개발 배포와 현재 앱 코드를 먼저 바꾸지 않는다.
- [DL-17436](https://innovaid.atlassian.net/browse/DL-17436)을 DL-16140 하위, Frankie 담당, **해야 할 일**로 생성하고 재조회했다. 기존 DL-17064의 완료된 랜딩 연결과 후속 호환 작업을 구분하며 SP는 지정하지 않았다.

## 재개할 때 확인할 순서

1. 1.93.0 배포 및 치과앱 주문 상세 정본의 실제 반영 위치·화면 route/params·대상 앱 버전을 확인한다. 1.93.0은 사용자가 말한 릴리즈 일정이며 앱 바이너리 버전으로 추정하지 않는다.
2. 기존 `appLandingUrl`과 푸시 `deeplink`가 새 화면으로 연결되는지 확인한다. **URL 자체 변경 없이 내부 라우팅만 대응할 수 있는지부터** 본다.
3. 로그인 준비·대상 병원 확인/전환·권한·뒤로가기와 `deliveryId` 읽음 연결을 유지한다. 주문 상세 기능 자체를 이 카드에서 중복 개발하지 않는다.
4. URL/필수 전달값 변경이 필요한 경우만 [랜딩 시트](https://docs.google.com/spreadsheets/d/1w1xwwEWRE0KgiJsOvldxIFbtNgWguohurf5kemIrW_g/edit?gid=614410508#gid=614410508) 수정 내용을 PM에게 전달하고 BE의 저장 주소에도 반영이 필요한지 공유한다. 시트는 DB가 아니므로 시트만 바꿔 완료로 보지 않는다. 변경이 불필요하면 유지 결론을 기록한다.
5. 새 화면이 실제 배포 대상 앱에 포함되는지 확인한 뒤 치과앱 iOS·Android에서 변경된 인박스/푸시 진입·복귀를 검증한다. 실제 푸시 발송 E2E는 별도 승인된 준비 단계에서 수행한다.

이메일 외부 링크·기공소앱 주문 상세·원 주문 상세 개발은 범위 밖이다. 다음 알림센터 재개 시 이 후속을 함께 알려주되 자동 폴링이나 1.93.0 배포 추적은 하지 않는다.
